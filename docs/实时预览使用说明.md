# 实时预览使用说明

本项目提供 `watch` 命令：启动后自动构建网站，监听源文件的保存，并刷新浏览器。日常写作只需要保持一个终端运行。

## 1. 快速开始

在 VS Code 中打开项目文件夹，再打开终端。确认当前目录中有 `build.py`。

如果不在项目目录，先在 PowerShell 中运行：

```powershell
Set-Location -LiteralPath 'E:\ruyi13.github.io'
```

启动实时预览：

```powershell
python build.py watch
```

首次启动会编译页面并复制资源，完成后终端显示：

```text
实时预览：http://127.0.0.1:8000
监听所有页面、.bib、模板、CSS 和图片。保存后自动更新；Ctrl+C 停止。
```

浏览器通常会自动打开。也可以手动访问：

```text
http://127.0.0.1:8000
```

修改 `.typ` 文件，按 **Ctrl+S** 保存。终端会显示检测到的修改和编译结果，浏览器随后自动刷新。更新速度取决于页面数量和编译耗时。

保持这个终端运行；关闭终端或按 **Ctrl+C** 会停止监听和预览服务。

## 2. 打开正在编辑的页面

首页与博客文章有不同的地址。保存文章后，需要在浏览器中打开对应的文章页面。

| 源文件 | 本地预览地址 |
| --- | --- |
| `content/index.typ` | `http://127.0.0.1:8000/` |
| `content/Blog/index.typ` | `http://127.0.0.1:8000/Blog/` |
| `content/Blog/2026-10-12-llm-refusal-direction/index.typ` | `http://127.0.0.1:8000/Blog/2026-10-12-llm-refusal-direction/` |

一般情况下，`content/某个目录/index.typ` 对应 `/某个目录/`。

实时刷新通过本地服务提供。请使用终端显示的 `http://127.0.0.1:端口` 地址；直接双击 `_site/index.html` 得到的 `file://` 页面不会获得实时刷新。GitHub Pages 上的线上网站需要完成推送和部署后才会更新。

## 3. 哪些修改会自动更新

| 修改位置 | 用途 | 保存后的行为 |
| --- | --- | --- |
| `content/` 下的 `.typ` | 首页、博客、文档和 PDF 源文件 | 重新编译 HTML 和 PDF，刷新网页 |
| `content/` 下的 `.bib` | 参考文献 | 重新编译，使引用和文献列表更新 |
| `content/` 下的图片、Markdown 等资源 | 页面配图和引用内容 | 同步资源并重新编译 |
| `config.typ` | 网站配置 | 重新编译页面 |
| `tufted-lib/` | 模板函数与排版 | 重新编译页面 |
| `assets/` 下的 CSS、JavaScript 和其他资源 | 网站样式与交互 | 同步资源，刷新网页 |

新增页面也会被检测到。若希望新文章出现在博客目录中，还需要在 `content/Blog/index.typ` 中添加对应的 `tufted.blog-entry()` 条目。

只修改编辑器里的文字、尚未保存到磁盘时，不会触发构建。修改 `build.py` 后，需要停止并重新启动 `watch`；说明文档和项目目录中的其他文件不在监听范围内。

请在 `content/`、`assets/` 等源目录中编辑。`_site/` 是构建产物目录，直接修改其中的文件可能在下次构建时被覆盖。

## 4. 常用启动选项

### 更换端口

如果提示端口被占用，先在旧预览终端按 **Ctrl+C**。也可以使用其他端口：

```powershell
python build.py watch -p 8001
```

此时应打开：

```text
http://127.0.0.1:8001
```

文章页面的地址也要使用同一个端口。

### 不自动打开浏览器

```powershell
python build.py watch --no-open
```

选项可以组合：

```powershell
python build.py watch -p 8001 --no-open
```

### 使用 uv

已经安装 uv 时，也可以运行：

```powershell
uv run build.py watch
```

`watch` 使用 Python 标准库，不需要安装 LiveReload。环境需要 Python 3.10 或更新版本，以及能通过 `typst` 命令调用的 Typst CLI；本项目建议使用 Typst 0.15 或更新版本。

## 5. 常见问题

### 保存后页面没有变化

依次检查：

1. 终端运行的是 `python build.py watch`，并且进程仍在运行。
2. 修改的文件已按 **Ctrl+S** 保存，位置在上一节列出的监听范围内。
3. 终端是否出现“检测到修改”。如果没有，确认文件属于当前项目。
4. 浏览器地址与终端显示的端口一致，并且打开的是正在修改的页面。
5. 终端是否出现编译错误；如果有，先修正错误再保存。

如果之前开着旧的 `preview` 服务或 `typst watch` 进程，建议先停止，再使用本说明中的单终端方式。重新启动预览服务后，若旧标签页没有自动连接，手动刷新一次即可。

### 终端显示编译失败

查看终端中的错误文件、行号和原因。例如：

- 引用的图片或 `.bib` 文件路径不存在。
- `@文献键` 与 `.bib` 中的条目键不一致。
- Typst 括号、字符串或函数调用写法有误。

失败页面会保留上一次成功编译的输出，浏览器底部会提示查看终端。修正错误并保存后，系统会再次尝试构建。某个页面首次编译就失败时，可能尚无可供预览的 HTML 文件。

### CSS 或图片没有更新

确认修改的是 `assets/` 或 `content/` 中的源文件，并且已保存。检查终端的构建结果，以及页面中引用的文件路径。新增图片后，还需要在 `.typ` 中使用正确路径引用它。

例如，与某篇文章的 `index.typ` 同目录下的 `imgs/example.png`，可以写成：

```typst
#image("imgs/example.png")
```

### 删除或移动文章后，旧地址仍然能打开

`watch` 会检测删除，但不会清理所有旧构建产物。删除或移动文章后，可以停止 `watch`，清理并完整重建，再启动：

```powershell
python build.py build --force
python build.py watch
```

`build --force` 会清理并重建 `_site/`。同时检查博客目录中是否还有指向旧文章的链接。

### 提示找不到 Python 或 Typst

在终端中确认：

```powershell
python --version
typst --version
```

若命令不存在，安装相应工具并将其加入 `PATH`，然后重新打开终端。若使用 uv，可以用 `uv run build.py watch` 管理脚本所需的 Python 环境；Typst CLI 仍需单独准备。

### 终端中文乱码或出现编码错误

可以在 PowerShell 中为当前终端启用 UTF-8 输出后再启动：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python build.py watch
```

## 6. watch、preview、build 的区别

| 命令 | 编译源文件 | 持续监听 | 浏览器刷新 | 适用场景 |
| --- | --- | --- | --- | --- |
| `python build.py watch` | 启动时及源文件变化后编译 | 是 | 自动刷新 | 日常写作、调样式、修改引用 |
| `python build.py preview` | 否 | 不监听源文件并自动编译 | 使用 LiveReload 时自动刷新；回退到普通 HTTP 服务时需手动刷新 | 查看已生成的网站 |
| `python build.py build` | 构建一次，默认采用增量编译 | 否 | 不提供预览服务 | 生成完整网站产物 |

`watch` 会编译页面和同步资源，但不会生成或更新 `sitemap.xml`、`robots.txt`、`feed.xml`。准备发布时，运行一次完整构建流程：

```powershell
python build.py build
```

然后按项目原有的 Git 推送与 GitHub Pages 部署流程发布。

## 7. 日常使用顺序

1. 打开项目，运行 `python build.py watch`。
2. 在浏览器中打开首页或目标文章。
3. 编辑源文件，按 **Ctrl+S**，等待编译并查看更新。
4. 出现错误时，按终端提示修正并再次保存。
5. 完成写作后按 **Ctrl+C** 停止预览；发布前运行 `python build.py build`。

实现位于 [build.py](../build.py)，自动构建与刷新逻辑的测试位于 [tests/test_live_preview.py](../tests/test_live_preview.py)。
